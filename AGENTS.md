# Working preferences

- Format long Go struct literals with one field per line. Wrap long calls and
  maps too; keep each structured-log key/value pair together on its own line.
- Keep configuration focused on demonstrated use cases. Prefer explicit config
  shipped with example content over protocol sniffing or extra required CLI flags.
- Keep README additions concise and operational. Put ordinary flag explanations
  in CLI help rather than documenting every implementation detail.
- Diagnostic output and design questions are not automatically requests for code
  changes. Explain findings first when the user is asking for analysis or a tradeoff.
